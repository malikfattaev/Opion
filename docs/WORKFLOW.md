# Рабочие соглашения

## Ветки

- `main`: то, что работает в проде. Пуш разворачивает деплой.
- `feat/<что>`, `fix/<что>`: рабочие ветки, вливаются через pull request.

## Коммиты

Одна короткая строка в повелительном наклонении, без описания и без точки в конце.

```
add product card
fix cart total rounding
update delivery copy
```

## Перед пушем

```bash
npm run typecheck
npm run lint
npm run build
```

Три команды в каждом проекте, который затронут изменения. Красная сборка в `main`
означает лежащий прод, Railway деплоит автоматически.

## Стиль кода

- TypeScript строгий, `any` не используем.
- Никаких «магических» значений в компонентах: константы живут в конфигах,
  секреты и адреса живут в переменных окружения.
- Комментарии объясняют «почему», а не пересказывают код.
