# Деплой

GitHub хранит код, Railway собирает и запускает. Пуш в `main` разворачивает прод.

## Сервисы в Railway

В одном проекте Railway поднимаются три сервиса:

| Сервис     | Источник           | Root Directory | Что делает            |
|------------|--------------------|----------------|-----------------------|
| `postgres` | шаблон Railway     | не нужен       | База данных           |
| `web`      | репозиторий GitHub | `web`          | Сайт и API            |
| `app`      | репозиторий GitHub | `app`          | Telegram Mini App     |

Root Directory обязателен: без него Railway попытается собрать корень монорепозитория.

## Переменные окружения

### web

| Переменная                 | Значение                             | Обязательна |
|----------------------------|--------------------------------------|-------------|
| `DATABASE_URL`             | `${{Postgres.DATABASE_URL}}`         | да          |
| `NEXT_PUBLIC_SITE_URL`     | `https://${{RAILWAY_PUBLIC_DOMAIN}}` | да          |
| `NEXT_PUBLIC_MINI_APP_URL` | публичный домен сервиса `app`        | нет         |
| `TELEGRAM_BOT_TOKEN`       | токен бота из @BotFather             | для заказов |
| `TELEGRAM_ORDERS_CHAT_ID`  | id группы, куда падают заказы        | для заказов |
| `PAYMENT_CARD_NUMBER`      | номер карты для перевода             | для заказов |
| `PAYMENT_CARD_HOLDER`      | имя держателя карты                  | нет         |
| `PAYMENT_BANK`             | название банка                       | нет         |

Без `TELEGRAM_*` и `PAYMENT_CARD_NUMBER` витрина работает, но оформление заказа
заблокировано: покупатель увидит понятное сообщение вместо реквизитов.

### app

| Переменная            | Значение                        |
|-----------------------|---------------------------------|
| `NEXT_PUBLIC_API_URL` | публичный домен сервиса `web`   |

Ссылки вида `${{Postgres.DATABASE_URL}}` Railway подставляет сам, копировать
строку подключения руками не нужно, при ротации пароля она обновится автоматически.

## Порт и проверка живости

Railway передаёт порт в переменной `PORT`. `next start` читает её самостоятельно,
дополнительная настройка не нужна.

Файлы `railway.json` Railway больше не читает, настройки сервиса задаются
в дашборде или через `railway api`. У сервиса `api` включён healthcheck на
`/health`, у `web` и `app` хватает значений по умолчанию.

## Миграции базы

Схема применяется перед каждым деплоем `api`: в настройках сервиса задана
pre-deploy команда `npm run db:deploy`. Вручную её запускать не нужно, но
при отладке можно:

```bash
railway run --service api npm run db:deploy
```

`prisma migrate deploy` только накатывает уже созданные миграции и никогда не удаляет
данные. Команда `prisma migrate dev` предназначена только для локальной разработки.

## Первый запуск

```bash
gh repo create opion --private --source=. --remote=origin --push
railway init
railway add --database postgres
railway up
```

Дальше в дашборде Railway для каждого сервиса задаётся Root Directory и переменные
окружения из таблиц выше.
