# Архитектура

## Сервисы

```
┌───────────────┐        ┌───────────────┐
│  web (сайт)   │        │  app (мини-   │
│  Next.js      │        │  апп Telegram)│
│  + API-роуты  │◀───────│  Next.js      │
└───────┬───────┘  HTTP  └───────────────┘
        │
        ▼
┌───────────────┐
│  PostgreSQL   │
│  (Railway)    │
└───────────────┘
```

**Один источник данных.** Доступ к базе есть только у `web`: там же живут Prisma-схема,
миграции и API-роуты. Мини-апп базу не трогает, он ходит в то же API по HTTP.
Так не появится двух расходящихся моделей данных и двух пулов соединений.

## Где что лежит

### web

```
web/
├── prisma/
│   ├── schema.prisma      Модель данных
│   └── migrations/        История изменений схемы
├── prisma.config.ts       Конфиг Prisma CLI (Prisma 7)
└── src/
    ├── app/               Роуты App Router и API
    ├── lib/
    │   ├── env.ts         Валидация переменных окружения
    │   └── db.ts          Prisma Client (один экземпляр на процесс)
    └── generated/prisma/  Сгенерированный клиент (в git не хранится)
```

### app

```
app/
└── src/
    ├── app/               Экраны мини-аппа
    └── lib/               Клиент API и обвязка Telegram SDK
```

## Соглашения

- **Переменные окружения** описываются в `.env.example` и валидируются в `src/lib/env.ts`.
  Ни одного `process.env.X` в обход этого модуля.
- **Prisma Client** создаётся ровно один раз (`src/lib/db.ts`), иначе hot reload плодит
  соединения до отказа базы.
- **Алиас `@/`** указывает на `src/`. Относительные пути вида `../../..` не используем.
- **Prisma 7** требует драйвер-адаптер (`@prisma/adapter-pg`) и явную загрузку `.env`
  через `dotenv` в `prisma.config.ts`: автоматической подгрузки больше нет.
